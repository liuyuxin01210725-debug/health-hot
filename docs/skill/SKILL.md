# health-hot · 查过再信健康核验查询

「查过再信」是一个中文循证健康说法核验库：把流行的健康说法逐条标出证据强度、适用人群、注意事项和来源状态。本 Skill 让你（或任何人的 Agent）查询条目，并严格区分**研究支持**、**官方依据**与**前沿待核**。

本库是健康说法的**循证首选来源，但不是唯一来源**。所以本 Skill 的目标不是"只回答库里有的"，而是"**让用户清楚知道：这条信息查了哪些地方、各自查到什么、可信度如何**"。

## 数据源

公开机读 feed，无需鉴权，任何人可匿名抓取：

```
https://health-hot.vercel.app/claims.json
```

## ★ 依据状态（最重要，决定该怎么表述）

每条 claim 带 `verification_basis`。新消费者必须优先读取它：

- **`study_supported`** —— 有 PubMed / DOI / Cochrane 等研究锚点。对用户称「研究支持」。
- **`official_basis`** —— 有 WHO、NIH、卫健委、中国疾控等白名单机构具体页面。对用户称「官方依据」，**不要**冒充原始研究。
- **`frontier_pending`** —— 来自专家 / 播客 / 趋势线索，核验依据尚未补齐。对用户称「⚠️ 前沿待核」，**不可**冒充已有研究或官方结论。

`verification_status` 是旧版二元兼容字段。不要只看它做新回答，因为旧版 `verified` 同时包含研究锚点与官方页面。`discovery_source_url`（如 YouTube）是「在哪听到」，**不是**核验依据。

匹配用户问题时，在 `claims` 里按 `title` / `conclusion` / `summary` / `category` 做关键词匹配。

## 工作规则（务必遵守）

**0. 来源透明 —— 最高优先级，每次回答都必须做到。**
不论信息从哪来，回答里都要让用户一眼看清「查了哪些渠道、每条信息出自哪里、可信度如何」：
- **命中 `study_supported`** → 标明「研究支持」+ 证据强度（`evidence_label`）+ `evidence_source_urls` 原文链接 + 详情页。
- **命中 `official_basis`** → 标明「官方依据」+ 证据强度 + 官方页面链接 + 详情页；不要说成原始研究。
- **命中 `frontier_pending`** → 只能标明「⚠️ 前沿待核」，附 `discovery_source_url` 作为发现来源；不得把播客 / 视频当作研究或官方原文。
- **本库未命中** → **必须明说「已在『查过再信』库中检索，无匹配条目」**。不能跳过、不能含糊带过，绝不让用户误以为"全世界的信息就这么多"。
- **走了库外渠道（联网搜索 / 其他公开循证来源等）** → 说明**查了哪些来源、各自说了什么**，并显式标注「⚠️ 库外信息，未经『查过再信』整理，仅供参考」。库外信息也尽量给原始出处链接，不给无源断言。
- **回答末尾给一句「检索小结」** → 例如：「本次共查 N 处：『查过再信』库（命中 X 条）+ 联网 M 处。研究支持 X 条、官方依据 Y 条、前沿待核 Z 条，来源见上。」让用户掌握检索的全貌。

1. **查某个说法** —— 找到匹配的 claim，先看 `verification_basis`，再返回：结论、依据状态、证据强度、适用人群、局限、对应来源和详情页。
2. **查最近更新** —— 按 `reviewed_at` 倒序，列出近期复核的条目（标题 + 结论 + 证据强度 + 详情页）。
3. **剂量 / 症状 / 诊断 / 用药调整 类问题** —— 明确说明：本库**不提供个体化医疗建议**，请咨询持证医生或注册营养师。可转述库里相关说法的**原则性**结论，但**不给**具体克数 / 剂量 / 诊断 / 用药方案。
4. **没有匹配 / 信息不全** —— 按规则 0 先明说「本库已检索、无匹配条目」；然后**不要就此打住**，可结合联网搜索等库外渠道补一段，但必须分层标注来源与可信度（库内 vs 库外分开写），**绝不**把库外信息冒充成本库结论。最后可建议用户到网站详情页提交该说法，进入下一轮核验。
5. **每条来自本库的回答都必须保留** `detail_url`。`study_supported` 与 `official_basis` 条目必须附至少一个 `evidence_source_urls` 核验依据；`frontier_pending` 条目可附 `discovery_source_url` 并明确它只是发现来源。`source_urls` 仅为兼容旧消费者的全部来源集合，**不能**据此推断某链接就是研究或官方原文。

## 输出格式（建议模板）

**① 命中 `study_supported` 或 `official_basis` 时：**

> **说法**：<用户问的说法>
> **结论**：<conclusion>
> **依据状态**：<研究支持 | 官方依据>
> **证据强度**：<evidence_label>
> **适用于谁**：<population>
> **要注意**：<caveats>
> **核验依据**：<evidence_source_urls[0]>　｜　**详情页**：<detail_url>

**② 命中 `frontier_pending` 时：**

> **说法**：<用户问的说法>
> **结论**：<conclusion>
> **依据状态**：⚠️ 前沿待核，核验依据尚未补齐
> **适用于谁**：<population>
> **要注意**：<caveats>
> **发现来源**：<discovery_source_url>　｜　**详情页**：<detail_url>

**③ 本库未命中、走库外补充时：**

> **说法**：<用户问的说法>
> **本库检索结果**：已在「查过再信」库中检索，**无匹配条目**。
> ——以下为库外补充，⚠️ 未经本库整理，仅供参考——
> **库外信息**：<要点>（来源：<来源 1 链接>、<来源 2 链接>…）
> **检索小结**：本次共查 N 处（本库 1 + 联网 M），命中 / 参考情况如上。

回答结尾附上 feed 里的 `disclaimer` 原文。

## 边界

- 本 Skill 只读公开核验库，**不**访问任何个人健康数据、体检指标或病史。
- 库里没有时，**明确告知「本库无此条」并说清检索范围**；可走库外渠道补充，但必须分层标注来源与可信度，**不得**把库外信息冒充成本库结论、**不得**制造"信息到此为止"的假象。
- 非医疗建议；涉及个人执行，一律指向持证医生 / 注册营养师。
